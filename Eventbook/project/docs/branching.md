# Модель ветвления проекта (GitHub Flow)

Для нашего учебного проекта выбрана упрощенная модель ветвления **GitHub Flow**, которая идеально подходит для небольших проектов и команд.

## Основные правила:
1. **Основная ветка (`main`)** всегда находится в стабильном и рабочем состоянии. Прямые коммиты в `main` запрещены правилами защиты ветки (Branch Protection Rules).
2. **Ветки задач (Feature branches)** создаются под каждую отдельную задачу из трекера. Название ветки формируется по шаблону: `feature/<id>-<описание>` или `docs/<id>-<описание>`.
3. **Слияние (Merge)** в `main` происходит исключительно через Pull Request после прохождения код-ревью.
