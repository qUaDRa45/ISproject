# Модель ветвления проекта (GitHub Flow)

Для нашего учебного проекта выбрана упрощенная модель ветвления **GitHub Flow**, которая идеально подходит для небольших проектов и команд.

## Основные правила и регламент:
1. **Основная ветка (`main`)** всегда находится в стабильном и рабочем состоянии. Прямые коммиты в `main` заблокированы правилами защиты (Branch Protection Rules).
2. **Ветки задач (Feature/Docs branches)** создаются под каждую отдельную задачу из трекера. Название ветки формируется по стандарту: `feature/<id>-<описание>` или `docs/<id>-<описание>`.
3. **Слияние (Merge)** в `main` происходит исключительно через Pull Request после прохождения обязательного код-ревью.
4. **Формат коммитов:** Все коммиты оформляются по спецификации **Conventional Commits** (`feat`, `fix`, `docs`, `chore`, `refactor`) с обязательным указанием номера задачи в скобках (например, `feat(#1): ...`).
