# ADR 001: Выбор архитектурного стиля и технологического стека (Монолит + FastAPI)

* **Статус:** Принято
* **Дата:** 2026-10-05

## Контекст
Проект разрабатывается одним разработчиком в рамках учебного задания в ограниченные сроки. Необходимо спроектировать надежную, легко развертываемую систему с возможностью быстрого тестирования API и минимальными накладными расходами на инфраструктуру.

## Рассматриваемые варианты
1. **Микросервисная архитектура (Node.js/Go/Python разрозненно + брокеры сообщений):**
   * *Плюсы:* Изолированность сервисов, высокая масштабируемость.
   * *Минусы:* Избыточная сложность оркестрации, огромные затраты времени на конфигурацию сети и инфраструктуры для соло-проекта.
2. **Классический монолит (Python / FastAPI + SQLite/PostgreSQL):**
   * *Плюсы:* Простота разработки, единый кодовая база, встроенная автодокументация Swagger, быстрая контейнеризация в один Docker-контейнер.
   * *Минусы:* Ограничения при горизонтальном масштабировании (неактуально для текущего объема задач).

## Решение
Выбран **монолитный подход** с использованием фреймворка **FastAPI (Python)** и реляционной базы данных **SQLite** (с возможностью легкой миграции на PostgreSQL через SQLAlchemy).

## Последствия
* **Плюсы:** Быстрый старт, минимальный порог входа, написание всей бизнес-логики в рамках одного проекта, отсутствие необходимости поднимать сложную инфраструктуру (Docker Compose поднимает приложение одной командой).
* **Минусы:** Вся логика приложения сосредоточена в одном сервисе, однако для масштаба учебного проекта это является оптимальным компромиссом.
