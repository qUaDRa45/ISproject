# Отчет о качестве кода и статическом анализе

## 1. Форматирование и линтинг (Ruff)
Для проверки чистоты кода использовался линтер **Ruff** с набором правил:
* `E`, `W` — соответствие стандарту PEP 8;
* `F` — поиск неиспользуемых импортов и переменных (Pyflakes);
* `I` — автоматическая сортировка импортов (isort);
* `B` — поиск распространенных логических ошибок (flake8-bugbear);
* `S` — базовый аудит безопасности (flake8-bandit).

### Выявленные и исправленные замечания:
1. **Сортировка импортов (`I001`):** В файлах `main.py` и `models.py` импорты сторонних библиотек были перемешаны с локальными модулями. Исправлено автоматически через `ruff check --fix`.
2. **Устаревший метод Pydantic (`W` / Deprecation):** В `main.py` вызов `event.dict()` заменен на актуальный для Pydantic v2 метод `event.model_dump()`.
3. **Форматирование:** Приведены к единому стилю кавычки (двойные) и отступы во всех `.py` файлах.

## 2. Статический анализ безопасности (Bandit)
Выполнена проверка директории `app/` командой `bandit -r app/`:
* **Просканировано строк кода:** ~115
* **Критичных уязвимостей (High/Medium):** 0
* **Примечания (Low):** Зафиксировано использование строки подключения SQLite по умолчанию (приемлемо для локального MVP, в продакшене выносится в переменные окружения `.env`).
